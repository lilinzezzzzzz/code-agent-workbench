# Worktree 环境设置

依据项目实际内容，为 Codex 托管 worktree 提供文件复制清单和 macOS 设置脚本。默认交付可审阅的候选内容；用户明确要求创建或更新 `.worktreeinclude` 时，在授权范围内落地。用户提出不同范围时遵从其要求。

## 调查与决策

1. 确定项目入口 checkout、目标起始分支和现有工作树状态；检查已有 `.worktreeinclude`、忽略规则、适用的项目指令、依赖锁文件、版本约束、初始化文档与实际加载路径。遵守仓库的搜索排除规则；不要输出密钥内容。
2. 按用途列出需复制的忽略文件、需重新生成的依赖或产物、可选文件和未知项，说明来源及证据。确认路径在来源 checkout 中存在且被 Git 忽略；不把已跟踪文件放入清单。判断配置与目标分支是否兼容；来源不明确或可能连接错误环境时标出，不猜测。
3. 对密钥、凭据和可能指向共享或生产资源的配置，说明用途、复制来源和风险；只纳入用户已授权或明确需要的最小范围。绝不输出秘密值或将其写入脚本、样例和日志。不要复制虚拟环境、缓存或日志，除非有明确的项目需要。
4. 合并现有 `.worktreeinclude` 时保留用户已有内容，使用足够精确的路径或模式，避免误复制其他忽略文件；核实通配符匹配范围和实际文件类型。明确区分 Codex 托管 worktree 与手工 Git worktree，前者的复制机制不能假定适用于后者。

## macOS 设置脚本

依据项目实际使用的工具、锁文件和版本要求编写可复制的 shell 脚本，安装依赖并按需生成资源。使用明确的失败处理；检查必要文件与配置时避免输出秘密、启动服务、修改共享数据或连接外部业务系统。环境选择、命令执行目录、网络需求及可能的安装成本应与项目证据一致；未证实的命令标为待验证。不要把某个项目的路径、工具或环境名称当作通用默认值。

默认输出脚本供用户在 Codex 本地环境设置中保存。未经核实，不把手工修改自动生成的 `environment.toml` 当作受支持接口；尊重其文件提示和用户指定的方式。清理脚本及启动服务是独立选择，不要隐含加入破坏性或共享资源操作。

## 验证与交付

- 对候选清单验证路径存在、忽略状态及匹配范围；对现有文件修改检查最终 diff，保留无关内容。
- 根据实际授权和环境选择安全的语法、安装或配置加载检查；明确列出实际执行的命令、结果及未验证项，避免将配置解析成功等同服务可用。
- 区分手动运行脚本、托管 worktree 文件复制、以及新聊天创建 worktree 时自动触发设置脚本的验证。需要完整自动验证时，应使用支持选择目标环境的实际创建流程；如不可用，报告缺口，不用手动运行代替自动运行的证据。
- 交付清单、来源、macOS 脚本、风险与验证步骤；说明实际是否修改了 `.worktreeinclude`，以及任何待决的配置来源或权限问题。
